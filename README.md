# polza-outreach-test

Тестовое задание Polza Agency на позицию «Вайбкодер-аутричер». Автор: Андрей Ермохин.
Всё сделано скриптами на Python, написанными в Claude Code; LLM внутри скриптов — Claude Haiku
через `claude -p` (подписка, без отдельного API-ключа).

**Google Таблица с результатами (задачи 1–4):**
https://docs.google.com/spreadsheets/d/1cBHMOQB1ZWEs5X-lRE0KuPxe2IsiUiBUD5mXGquCZaA

| Задача | Где смотреть |
|---|---|
| 1. База 50+ компаний | лист «База 50+» в таблице; скрипт `outreach/enrich.py` |
| 2. Персонализация | колонки «Персонализация / Источник / Цитата-подтверждение» там же; скрипт `outreach/personalize.py` |
| 3. Цепочка писем | лист «Цепочка писем» и `docs/email_sequence.md` |
| 4. База Polza (15 компаний) | лист «База Polza (15)» + `out/polza15_audit.xlsx`; скрипт тот же, флаг `--audit` |
| 5. Вайбкод/LLM-стек | `docs/STACK.md` |

## Как это устроено

```
seeds.csv (название, сайт, сегмент)            ← кандидатов искал агентами Claude Code по рейтингам,
        │                                        каталогам партнёров, hh.ru (вакансии продажников)
        ▼
outreach/enrich.py      сайт → страницы «контакты / о компании / политика» →
                        e-mail (свой домен > именной > sales@ > info@) →
                        ИНН из подвала → ЕГРЮЛ (DaData) → юрлицо и ФИО директора →
                        ЛПР со страницы команды (LLM + проверка цитаты) →
                        проверка e-mail: синтаксис, MX, домен = домену сайта
        ▼
outreach/personalize.py сайт → до 6 страниц «о компании / новости / кейсы / продукты» →
                        LLM пишет 1–2 предложения + ДОСЛОВНУЮ цитату-источник →
                        скрипт проверяет, что цитата есть в скачанном тексте →
                        колонки «Персонализация», «Источник», «Цитата», «Статус»
                        (--audit: плюс проверка чужой базы на подвохи)
        ▼
CSV / XLSX / Google Sheet (gspread)
```

Главный принцип: **нет цитаты с сайта — нет факта.** Модель может красиво придумать, поэтому
каждая персонализация опирается на дословный фрагмент, который скрипт нашёл в HTML. Если не нашёл,
в статусе так и написано: «НЕ ПОДТВЕРЖДЕНО, проверить вручную».

## Запуск

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export DADATA_API_KEY=...            # бесплатный ключ dadata.ru, для ЕГРЮЛ (можно без него)
# LLM: по умолчанию claude CLI; иначе ANTHROPIC_API_KEY или GEMINI_API_KEY (OUTREACH_LLM=gemini)

# задача 1: семена → база
python -m outreach.enrich --in seeds.csv --out out/base.csv --workers 8

# задача 2: база → база с персонализацией (+ сразу в Google Таблицу)
python -m outreach.personalize --in out/base.csv --out out/base_personalized.xlsx \
    --push-sheet <SPREADSHEET_ID> --push-worksheet "База 50+"

# задача 4: чужая таблица (даже без заголовка) → персонализация + проверка нестыковок
python -m outreach.personalize --sheet <ID_ЧУЖОЙ_ТАБЛИЦЫ> --out out/polza15_audit.xlsx --audit

# тесты и линтер (то же гоняет GitHub Actions)
pip install -r requirements-dev.txt && ruff check . && pytest -q
```

Формат входа для `enrich.py`: CSV с колонками `name,site[,segment,city,why_b2b,email_seen,source_url]`.
`personalize.py` понимает CSV/XLSX/Google Sheet, сам находит колонки «Компания/Сайт/Email» по синонимам
и умеет таблицу без заголовка.

## Что проверяет режим `--audit` (задача 4)

- домен e-mail ≠ домену сайта (и что реально открывается по обоим доменам);
- один и тот же сайт в двух строках;
- домен e-mail без MX-записей (письмо не дойдёт), публичная почта (126.com, gmail);
- на сайте другая компания, чем в колонке «название» (LLM сверяет с текстом сайта);
- компания не из России (ЦА Polza — российский B2B).

Результат — колонка «Проверка строки» с перечислением найденного и колонки «Что реально на сайте» /
«Что на домене e-mail», чтобы перепутанные строки можно было собрать обратно.

## Ограничения, честно

- **SMTP-проверка адресов не делалась**: на VPS закрыт исходящий 25-й порт. Поэтому «валидность» здесь =
  синтаксис + MX домена + совпадение с доменом сайта + адрес взят с самого сайта. В боевом запуске
  добавил бы верификатор (MillionVerifier / Hunter / свой SMTP-пробник с чистого IP), код для RCPT-пробы в
  `outreach/validate.py` уже есть, флаг `--smtp`.
- Именные адреса ЛПР на сайтах российских B2B встречаются редко; в базе основная масса — `sales@`/`info@`
  с сайта плюс имя ЛПР из ЕГРЮЛ или страницы команды. Именной ящик обычно подбирается по паттерну домена
  (i.ivanov@) и проверяется верификатором — это следующий шаг, не вошедший в тестовое.
- Рейтинги (Рейтинг Рунета, Tagline) отдают списки только через JS — кандидатов брал через статьи,
  каталоги партнёров и поиск; парсер на Playwright для них писать не стал ради 2 дней.
- LLM-часть в CI не гоняется (нестабильно и платно); в CI — линтер и юнит-тесты чистых функций.

## Структура

```
outreach/common.py       HTTP с кешем, HTML→текст, домены, извлечение e-mail
outreach/enrich.py       задача 1
outreach/personalize.py  задачи 2 и 4
outreach/validate.py     проверка e-mail (синтаксис, MX, SMTP по флагу)
outreach/dadata.py       ЕГРЮЛ через DaData
outreach/llm.py          claude -p / Anthropic API / Gemini, строгий JSON
outreach/sheets.py       Google Sheets через gspread
tests/                   pytest, без сети и без LLM
docs/                    цепочка писем, стек
```
